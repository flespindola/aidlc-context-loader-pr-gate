# User Stories Plan

## Persona development approach

The requirements say the rules and the home page are for people working in the repo. The game has no player yet. The question below decides whether that is one persona or two.

## Story format

Stories use: As a [persona], I want [goal], so that [benefit].

Each story must be independent, negotiable, valuable, estimable, small, and testable. Acceptance criteria use Given/When/Then. Tests are written after the code, matching the team practice.

## Story prioritization

MoSCoW follows the approved requirements. The home page, the five rule files, the frontmatter check, and the tests are Must Have. Gameplay, accounts, scores, saved progress, lookup by tag, and any deploy are Won't Have for this phase. Delivery Planning will set the formal MVP boundary later.

## Breakdown approach options

By the slice: the app, the rule library, and the checks. The question below sets how small each story is.
